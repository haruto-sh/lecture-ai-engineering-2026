- 検索だけを実行して見つかったページと、その本文で確認できたこと：`uv run python -m app.retrieval "LoRA QLoRA 違い"`では上位5件が返った。第2回・PDF p.52で「元の重みは固定し、小さな差分だけを学習」「LoRAはA・Bだけを学習」「QLoRAは元の重みを4bit圧縮」を確認できた。p.51でもLoRAが本体を固定し小さな追加部分だけ更新すること、QLoRAが本体を4bit圧縮することを確認できた。p.60・p.47・p.61は演習や関連説明であり、この質問の直接根拠ではない。
- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：通常のベクトル検索では`search_materials({'query': 'LoRA QLoRA 固定 学習 第2回'})`を1回呼び出した。Treeでは`browse_tree({})`で講義一覧を開き、`browse_tree({'node_id': 'lec02-main'})`、`browse_tree({'node_id': 'lec02-main-s045'})`、`browse_tree({'node_id': 'lec02-main-p052'})`の計4回で第2回の章からp.52を取得した。本文717文字を取得した。Graphでは`search_graph({'query': 'LoRA QLoRA 固定 学習'})`を1回呼び出し、入口としてp.52が返った。全文投入では検索ツール呼び出しはなかった。
- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：全文投入ではp.51、p.52を参照先として示したが、A・Bや4bit量子化による省メモリ効果を具体的に書かなかったため、取得可能な資料の核心を十分に使い切れていない。一方、検索系ではp.52を直接取得でき、回答へ具体的な根拠として使えた。検索だけではp.60・p.47・p.61など関連性の低いページも上位に混ざったが、回答生成で直接使用する必要はなかった。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：この質問ではベクトル検索が最も効率的だった。時間2.73秒、入力3,037トークンで正確な回答と根拠を得られ、回答が直接的で費用も低かった。Treeは正確だが目次を段階的にたどるため時間とトークンが最大になった。Graphは正確かつベクトル検索より費用・入力は高かった。全文投入は必要な資料をすべて渡せるが、今回も回答がヒント止まりになった。なお、全文投入は対象資料範囲が異なるため、厳密な公平比較ではない。時間・トークン・費用は1回の実行結果であり、実行ごとの差がある。
- 気づき・疑問：LoRAは元の重みWを固定し、低ランクの差分行列A・Bだけを学習するため、学習対象を抑えられる。QLoRAはこれに加えて元の重みを4bitで保持し、省メモリ化する。p.52がこの質問を解くための十分な根拠であり、p.51は概念の補足として有用だった。
